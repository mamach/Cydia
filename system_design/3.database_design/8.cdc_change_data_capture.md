# Change Data Capture (CDC)
- CDC is like database trigger but on steroids.

## What is CDC
- Data can live in many data sources.

- CDC is **design pattern**.

- CDC tracks and records changes in database as they happen.

# How CDC Work
- There are 3 ways to do this.
	- Trigger Based(impacts DB performance)
	- Polling(less efficient)
	- Log Based(better than trigger based and polling)


# Usecase with Example

- Example with debezium and kafka.
1. mysql records changes in binary log.
2. Debezium Connector - a kafka connector service with debezium reads these changes.
3. Event Creation: Debezium converts the changes into events.
4. Event Routing: These events are sent to kafka streams based on table.
5. Data Consumption: Other systems can then read these events from kafka and update themselves.


# When to use CDC
- Real time updates.
- Building event driven systems.
- Updating data warehouses: keep your data warehouse up-to-date with minimal delay.
- Microservices: Ensure all your services have latest data.

# Challenges with CDC
- CDC slows down main database.
- Scalability: Handling large volumes of data changes can be tricky.
- Consistency: Ensuring data stays consistent across systems.
- Latency: Keeping the delay between change and update as short as possible.
